# 阿里云部署

**可以，建议用 Docker Compose 部署到阿里云。** 但你要部署的是当前修改过的项目，需要构建自己的镜像；官方文档里的 `whyour/qinglong:latest` 是官方版本，不包含你的脚本结果浏览、下载接口等改动。

我核对了仓库，已经有 Dockerfile 和 Compose 配置，可以沿用。

**1. 服务器准备**

建议使用 Ubuntu 24.04。服务器安装 Docker Engine 和 Compose 插件，参考 [Docker 官方安装步骤](https://docs.docker.com/engine/install/ubuntu/)。

安装后确认：

```bash
docker version
docker compose version
```

运行阶段由容器提供 Node、Python；如果在服务器上构建前端，还需要安装 **Node 22、pnpm 8.3.1 和 Git**。

**2. 构建你自己的镜像**

下面是在 Linux Bash 中执行的示例。先确保要部署的代码已经提交并推送到你的仓库：

```bash
git clone --branch release_v1.0 \
  https://github.com/CyberXavier/qinglong.git \
  qinglong-src

cd qinglong-src

# 当前前端构建要求 Node 22
node --version

npm install -g pnpm@8.3.1
pnpm install --frozen-lockfile

pnpm build:front
pnpm build:back
pnpm build:info

docker build \
  -f docker/Dockerfile.debian \
  --build-arg QL_URL=https://github.com/CyberXavier/qinglong.git \
  --build-arg QL_BRANCH=release_v1.0 \
  --build-arg SOURCE_COMMIT="$(git rev-parse HEAD)" \
  -t qinglong-custom:release-v1 .
```

这里选择 Debian 镜像，方便安装 Python 爬虫依赖。**具体爬虫包仍需验证与容器内 Python 3.11 的兼容性。**

当前 [Dockerfile.debian](D:/WorkSpace/qinglong/docker/Dockerfile.debian:94) 会重新拉取源码，并校验构建产物，因此仓库地址、分支、提交必须一致，不能只把本地代码目录直接传进去构建。

**3. 用 Compose 启动**

创建独立的部署目录：

```bash
mkdir -p /opt/qinglong/data
cd /opt/qinglong
```

在这里保存 `compose.yaml`：

```yaml
services:
  qinglong:
    image: reg01.sky-mobi.com/dev-tools/qinglong:release-v1
    container_name: qinglong
    hostname: qinglong
    restart: unless-stopped
    ports:
      - "5700:5700"
    volumes:
      - ./data:/ql/data
    environment:
      TZ: Asia/Shanghai
      QlBaseUrl: "/"
      QlPort: "5700"
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
```

启动并检查：

```bash
# 登录公司镜像仓库
sudo docker login reg01.sky-mobi.com

# 检查配置并拉取镜像
sudo docker compose config
sudo docker compose pull

# 启动并检查状态
sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail 100 qinglong

# 检查服务是否就绪
curl -f http://127.0.0.1:5700/api/health
```

这种端口映射、数据挂载和启动方式与[青龙官方 Compose 文档](https://qinglong.online/guide/getting-started/installation-guide/docker-compose)一致。

**4. 阿里云开放访问**

在 ECS 安全组添加入站规则：**TCP 5700，来源填写你的公网 IP `/32`**；如果服务器还有系统防火墙，也需要允许访问该端口。安全组可以按来源 IP 和目标端口控制访问，见[阿里云说明](https://www.alibabacloud.com/help/en/ecs/user-guide/security-group-rules)。

随后在浏览器访问 `http://服务器公网IP:5700`，完成初始化。需要长期通过公网访问时，再配置域名和 HTTPS 反向代理。

**5. 数据和后续更新**

容器内 `/ql/data` 对应服务器 `/opt/qinglong/data`，你的结果目录对应：

```text
/opt/qinglong/data/res
```

脚本应把结果写入 `/ql/data/res` 下；需要的 Python、Node 依赖在面板依赖管理中安装。首次挂载空数据目录会遮蔽镜像中该路径预装的 Python 依赖，官方文档也特别说明了这一点。[依赖说明](https://qinglong.online/guide/getting-started/installation-guide/docker)

后续更新就是：**备份 data → 构建新版本镜像 → 修改 Compose 镜像标签 → `docker compose up -d`**。你这个定制版本应按自己的发布流程更新。
